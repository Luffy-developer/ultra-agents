# 第 10 课：评估与上线

## 核心概念
- **评估**：Agent 的回答每次都不完全一样，不能只凭"感觉还行"。要准备一组**测试题**，每次改 Prompt 或换模型后都跑一遍，对比效果。
  - 例：准备 20 个典型学生提问，检查导师是否都先读了讲义、是否出了小测验、有没有讲错。
  - 也可以让另一个大模型当"裁判"打分（LLM-as-a-Judge）。
- **安全**：
  - API Key 放在配置文件或环境变量里，绝不写进代码、不发给别人（本项目存在 `~/.agent-tutor/config.json`，权限设为只有自己能读）
  - 限制工具权限（本项目的文件工具只能访问练习目录）
  - 危险操作先问人（本项目写文件、运行命令前都会弹出「允许吗？」）
  - 限制循环次数（本项目的 `MAX_STEPS`），防止无限调用烧钱
- **上线**：
  - 做成别人能用的形态：本项目就是一个命令行工具，发布到 npm 后，别人 `npm install -g` 就能用
  - 也可以做成网页、聊天机器人等
  - 记录日志，观察真实用户在哪里卡住，持续改进

## 比喻
评估 = 新菜上架前先请人试吃打分；安全 = 后厨的门要上锁；上线 = 正式开门营业，还要收集顾客反馈。

## 毕业项目
用学到的知识，做一个**你自己的 Agent**：比如"记账助手"、"英语陪练"、"旅行规划师"。
可以直接复制本项目，改 System Prompt、换工具、换知识库。

## 小测验
问：为什么改了 Prompt 之后要重新跑一遍测试题？
答：因为改动可能让某些情况变好、另一些情况变差，只有用同一组题对比才能确认是真的变好了。
