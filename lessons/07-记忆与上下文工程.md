# 第 7 课：记忆与上下文工程

> **学完你能**：说清 Agent 的「记忆」是怎么用代码做出来的；说出上下文塞太满会出哪四种问题、各怎么办；知道长任务里管理上下文的三种办法；亲手写出不会把工具调用拆散的对话裁剪和压缩。

## 基础

### 1. 模型没有记忆，「记忆」都是代码做的
- 第 1 课「大模型是什么」说过：模型每次调用都是全新的。Agent 的"记忆"，是我们用代码决定**这一次把哪些内容塞给模型**。
- **短期记忆**：就是 `messages` 列表——本次对话的全部历史。越聊越长，会超出模型的上下文长度，也越来越贵。
- **长期记忆**：把重要信息存到文件或数据库里，下次需要时读回来。
- 比喻：短期记忆 = 你脑子里正在想的事（容量有限，聊完就忘）；长期记忆 = 你的笔记本（写下来，下次翻开还在）。

### 2. 上下文不是越多越好：「上下文腐烂」
- 很多人以为：上下文窗口有 100 万 token，那就什么都塞进去。Anthropic 的经验正好相反：**窗口越满，模型越抓不住重点、越容易忘掉前面的信息**，这叫「上下文腐烂」（context rot）
- 所以要把上下文当成一笔有限的**注意力预算**：目标是用**最少、最有用**的 token，让模型做好这一步
- 这门手艺就叫**上下文工程**：决定每一步给模型看什么、不给它看什么。它是这一年各家 Agent 课程最强调的主题之一
- 比喻：给同事交接工作，丢给他一整箱文件，不如给他一页写清重点的交接单

### 3. 上下文出问题的四种情况（来自微软 AI Agents for Beginners 第 12 课）
| 问题 | 是什么 | 怎么办 |
|---|---|---|
| **中毒** | 模型编出来的错误信息被写进上下文，之后被反复当成事实引用 | 写进记忆之前先核对 |
| **分心** | 历史太长，模型盯着旧信息，忽略了眼前的任务 | 定期把旧对话总结成摘要 |
| **混乱** | 塞了太多用不上的东西（比如几十个工具），模型不知道该看哪个 | 只放这一步用得上的 |
| **冲突** | 上下文里前后信息互相矛盾 | 及时删掉过时的信息 |

### 4. 短期记忆的三个难题和做法
1. **关掉程序就没了** → 存档：每说完一轮就把对话存成文件，下次读回来接着聊
2. **越聊越长** → 压缩：让模型把旧对话**总结**成一份"交接笔记"，替换掉原文，只保留最近几轮原文（就像把一整本课堂笔记浓缩成一页复习提纲）
3. **实在太长又总结失败** → 兜底：直接丢掉最早的几轮
- 注意：删或压缩旧对话时，**模型想调用工具的那条消息和工具结果要一起留或一起删**。只剩下工具结果、找不到对应的调用，接口会报错，模型也会糊涂

### 5. 长期记忆：两种来源，两种写法
**两种来源**
- **Agent 自己记的**：上课时发现你的特点（怕长代码、喜欢做饭的比喻），自己记下来。好的记忆要能**新增、修改、删除**：情况变了要更新，重复的要合并，不然越记越乱（这也是在防"中毒"和"冲突"）
- **你亲手写的**：一份说明文件，写下你的要求，Agent 每次开始前都读一遍，只读不改。Claude Code 的 `CLAUDE.md` 就是这个思路

**两种写法**（来自 LangChain Academy 第 5 模块）
- **用户画像（profile）**：一份**不断更新的文档**，比如 `{"姓名": …, "基础": "会 Python", "喜好": "做饭的比喻"}`。有新信息就改这一份，永远只有一份
- **集合（collection）**：**一条条独立的记录**，比如"m1：怕看长代码""m2：喜欢先看例子"。有新信息就加一条，过时的删掉
- 怎么选：信息项是固定的几样（像一张表格）→ 用户画像；零零散散、数量不定 → 集合

### 6. 看看本项目
- **长期记忆（集合写法）**：`~/.agent-tutor/progress.json` 里的 `memories`。导师用 `remember` 新增、`update_memory` 修改、`forget` 删除；超过 20 条会提醒导师合并。输入 `/memory` 就能看到导师记住了你什么。代码在 `src/memory.ts`
- **长期记忆的另一个例子：错题本**。你答错的题会记进 `progress.json` 的 `reviews`，按「三个盒子」安排复习：答错放进第 1 盒，复习答对升一盒，第 1/2/3 盒分别隔 1/3/5 天再复习，第 3 盒再答对就移出错题本。导师每次上课先用 `get_progress` 读出今天到期的错题。输入 `/progress` 查看
- **说明文件**：`TUTOR.md`。写在 `~/.agent-tutor/` 里对所有目录生效，写在练习目录里只对这个目录生效
- **存档与恢复**：每轮自动存到 `~/.agent-tutor/sessions/`（只保留最近 30 个）。`agent-tutor --continue` 接着上次聊，`/resume` 挑一个历史对话。代码在 `src/session.ts`
- **压缩**：对话超过 20 万字符时自动压缩，也可以手动输入 `/compact`。代码在 `src/agent.ts` 的 `compactHistory`：保留最近两轮原文，前面的交给模型写成交接笔记；切分点按"学生说话"的位置找，保证工具调用和结果不会被拆开。总结失败时，`trimHistory` 从最早的一轮开始整轮丢弃

### 7. 动手试试
1. 新建 `~/.agent-tutor/TUTOR.md`，写一句你希望导师怎么教你，比如"每讲完一个知识点，先让我用自己的话复述一遍"
2. 输入 `/clear` 开始新对话（新对话才会读到新的 TUTOR.md），看导师有没有照做
3. 输入 `/memory`，看看导师记住了你哪些事

## 进阶

### 1. 长任务管理上下文的三种办法（来自 Anthropic《Effective context engineering for AI agents》）
- **压缩（compaction）**：快满时把旧内容总结掉。写总结的提示词要先保证**不漏掉重要的**，再追求精简。最轻的一种压缩是**清掉旧的工具结果**——几十轮前读过的网页全文，现在已经用不上了
- **结构化笔记**：让 Agent 把进度、待办、发现写到上下文**外面**的文件里（如 `NOTES.md`、待办清单），需要时再读回来。本项目的 `todo_write` 就是这个思路
- **子 Agent**：把要读大量资料的子任务交给子 Agent，它在自己干净的上下文里干活，只交回一份 1000~2000 token 的摘要（第 11 课「多 Agent 与框架」）
- 怎么选：来回对话很多的长对话 → 压缩；有明确阶段、要反复迭代的任务 → 笔记；可以同时展开的调研 → 子 Agent

### 2. 按需加载（just-in-time）
- 不要一开始就把所有资料塞进上下文，只放**引用**（文件路径、网址、名字），让 Agent 需要时用工具去读，一层层展开
- 本项目的 **Skills**（技能）就是这样：System Prompt 里只列出技能的名字和一句话说明，导师觉得用得上时才调用 `use_skill` 读全文——这叫**渐进式披露**，就像书架上的书，平时只看书脊上的书名
  - 自带两个技能：`study-plan`（定学习计划）、`explain-code`（逐段给小白讲代码），输入 `/skills` 查看
  - 自己写一个：在 `~/.agent-tutor/skills/技能名/SKILL.md` 里写好名字、说明和步骤，格式和 Claude Code 的 Skills 一样
- 讲义也是：导师讲课前才用 `read_lesson` 读那一节，而不是把 16 节课全塞进 System Prompt

### 3. 上下文的格式由你决定（12-factor-agents 第 3 条）
- 上下文不一定是标准的"一问一答"消息列表。你可以把事件、工具结果按自己的格式打包，比如用 XML 标签把一次工具调用和结果写成紧凑的一小段
- 好处：信息更密，同样的 token 装更多有用的东西；也方便在打包时过滤掉敏感数据

### 4. 跨多次会话的长任务（来自 Anthropic《Effective harnesses for long-running agents》）
一个任务大到一次对话做不完（比如从零写一个应用），怎么让下一次对话接得上？
- 第一次对话先让 Agent 生成一份**功能清单**，用 JSON 写（Anthropic 发现模型比较少乱改 JSON 文件）
- 之后每次对话**只做一个功能**；做完用 git 提交，并更新进度文件
- 新的对话开始时，先读进度文件和 `git log`，再跑一遍简单的测试，确认现在的状态没问题，再接着做

## 常见误区
- ❌ "上下文窗口越大，塞得越多越好" → ✅ 塞得越满，模型越抓不住重点；只放这一步用得上的
- ❌ "Agent 自己会记住之前说过的话" → ✅ 模型没有记忆，是代码每次把历史一起发给它
- ❌ "删旧消息时一条条删就行" → ✅ 工具调用和它的结果要一起留或一起删，否则会报错
- ❌ "记忆只管往里加" → ✅ 过时的要改、重复的要合并、错的要删，否则会"中毒""冲突"
- ❌ "压缩就只能让模型写总结" → ✅ 最轻的办法是先清掉旧的工具结果，还不够再总结
