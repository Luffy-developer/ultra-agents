# 第 15 课（选修）：编程 Agent

本课是选修课，学完第 1~13 课后感兴趣再学。

> **学完你能**：把一个编程 Agent（比如 Claude Code，或者你正在用的这个导师）拆成前面学过的一块块零件；说清楚为什么写代码特别适合交给 Agent；知道让 Agent 改代码、跑命令时要守住哪些安全边界。

## 基础

### 1. 编程 Agent 就是「工具换成了文件和终端」的 Agent
- 编程 Agent 能读你的代码、改文件、运行命令、帮你修 bug。Claude Code 官方文档的介绍是：它会读你的代码库、修改文件、运行命令，并接入你的开发工具。
- 它的本质和第 5 课「Agent 循环」一模一样：模型想一步 → 调用一个工具（读文件、改文件、跑测试）→ 看结果 → 再想下一步……直到任务完成。
- 比喻：普通聊天机器人像一位只能隔着电话指导你修电脑的师傅；编程 Agent 像师傅坐到了你电脑前，自己动手查、改、试。

### 2. 拆开看：编程 Agent 由哪些零件组成
你正在用的 agent-tutor 本身就是一个小小的编程 Agent。下面每一项都标出了在本项目的哪里，以及是前面哪一课讲的：

| 零件 | 本项目的实现 | 对应的课 |
|---|---|---|
| 读文件、新建文件 | `read_file`、`write_file`（`src/tools.ts`） | 第 4 课「工具调用」 |
| 只改某几行 | `edit_file` | 第 4 课「工具调用」 |
| 按名字找文件、按内容找代码 | `glob`、`grep` | 第 4 课「工具调用」 |
| 运行命令 | `run_command` | 第 4 课「工具调用」 |
| 想一步做一步 | `runTurn` 里的循环（`src/agent.ts`） | 第 5 课「Agent 循环」 |
| 先列清单再动手 | `todo_write`（`src/todo.ts`） | 第 5 课「Agent 循环」 |
| 对话太长就压缩 | `compactHistory`、`/compact` | 第 7 课「记忆与上下文工程」 |
| 项目说明文件 | `TUTOR.md`（`src/memory.ts`） | 第 7 课「记忆与上下文工程」 |
| 接入外部工具 | MCP（`src/mcp.ts`） | 第 10 课「MCP 与 A2A」 |
| 派子 Agent 干独立的活 | `task` 工具（`src/subagents.ts`） | 第 11 课「多 Agent 与框架」 |
| 危险操作先问人 | 写文件、改文件、运行命令前弹出「允许吗？」 | 第 12 课「安全、护栏与人工介入」 |
| 每次都必须发生的规则 | Hooks（`src/hooks.ts`） | 第 4 课「工具调用」、第 12 课 |

你会发现：**编程 Agent 没有什么神秘的新技术，就是把前面每一课的零件组装在一起。**

### 3. 几个关键零件，细看一下
- **精确修改（`edit_file`）**：改文件时不整个重写，只把某一段文字换掉。它要求被替换的原文（`old_string`）在文件里**只出现一次**，出现多次就报错，让模型多带几行上下文——这是第 4 课讲的「防呆设计」：让工具很难被用错，不会改错地方。
- **找代码（`glob`、`grep`）**：代码库可能有成千上万个文件，一个个读会撑爆上下文。先按文件名或关键字找到相关的几处，再精读，这正是第 7 课说的「按需加载」。
- **说明文件**：Claude Code 每次开始时会读项目根目录的 `CLAUDE.md`，里面可以写代码规范、架构决定、常用的库；本项目对应的是 `TUTOR.md`。相当于给新来的同事一份「入职须知」，不用每次重复交代。
- **子 Agent**：Claude Code 官方文档说，每个子 Agent 有**自己的上下文窗口**、自己的提示词和工具权限；适合把会产生大量搜索结果、日志的支线任务交给它，它做完只把总结交回来，主对话保持清爽。本项目的出题官、调研员也是这样。
- **Hooks**：在工具调用前后自动运行你写的命令，比如每改完一个文件就自动格式化。Claude Code 和本项目的约定一样：工具调用前的 hook 以**退出码 2** 结束，就拦下这次调用。

### 4. 权限：哪些操作要先问你
编程 Agent 能改文件、跑命令，权力很大，所以要分级管：
- **本项目**：读文件、搜索不用问；写文件、改文件、运行命令、领取作业前都会弹出「允许吗？」；文件工具只能访问练习目录（`insideCwd` 函数检查路径）。
- **Claude Code**（官方权限文档）：读文件和 grep 在工作目录里不用审批；运行命令、修改文件、访问网页默认要审批。规则按 **deny（禁止）→ ask（询问）→ allow（允许）** 的顺序判断，禁止规则优先，一条宽泛的禁止规则不会被更具体的允许规则绕过。
- 还有几种权限模式可以切换，比如 `plan` 模式只读、只调查不改源文件，适合先让 Agent 出方案、你看过再动手。

## 进阶

### 1. 为什么写代码特别适合交给 Agent
Anthropic《Building effective agents》附录 1 给出的理由：
- **代码的对错可以用自动化测试来验证**
- **Agent 可以把测试结果当反馈，一轮轮改进**（测试报错 → 改代码 → 再跑测试，这就是第 5 课的循环）
- 问题定义清楚、结构明确，输出质量也能客观衡量
- 但他们也强调：**人工审查仍然很关键**，要确认改动符合系统整体的要求

这也是本课程动手作业的设计思路：每份作业都有检查脚本，Agent（或你）改完代码马上就能知道对不对。

### 2. 工具设计比提示词更值得花时间
同一篇文章附录 2 讲了他们做 SWE-bench（一个让 Agent 修真实 GitHub 问题的评测）编程 Agent 的经验：
- 他们花在优化**工具**上的时间，比优化整体提示词还多
- 模型离开项目根目录后，用相对路径就容易出错；把工具改成**必须填绝对路径**后，模型就用得完全没问题了

### 3. 长任务：跨好几次对话的 harness
上下文窗口有限，一个大项目一次对话做不完。Anthropic《Effective harnesses for long-running agents》的做法（harness 可以理解为「给 Agent 搭的工作台」）：
- **第一次对话由「初始化 Agent」搭好工作台**：一个启动开发环境的 `init.sh`、一个记录进度的 `claude-progress.txt`、一次初始的 git 提交
- **把需求展开成功能清单**，全部先标成「未通过」。清单用 **JSON** 写，因为文章发现模型比较不会乱改、乱删 JSON 文件（相比 Markdown）；编程 Agent 只能改「是否通过」这一项
- **每次对话只做一个功能**，结束时提交 git、更新进度文件。这样针对的是 Agent「一次想做太多」的毛病
- **新对话开工前**：先确认工作目录，读 git 记录和进度文件，挑一个优先级最高的未完成功能，再跑一遍基本的端到端测试，看看上一次有没有留下 bug
- 他们还发现：Agent 常常只跑了单元测试或简单请求就宣布「做完了」；让它用浏览器自动化**像真实用户一样去测**，效果明显变好

这和第 7 课讲的「结构化笔记」是同一个思路：把进度写在上下文窗口之外。

### 4. 安全：命令和沙箱
- 运行命令是编程 Agent 最危险的能力：一条命令可以删文件、把数据发到网上。按第 9 课的「致命三要素」看，编程 Agent 同时具备读私有代码、读外部内容（网页、依赖包里的文字）、对外通信的能力，最容易被提示注入利用。
- Claude Code 官方文档把**权限**和**沙箱**当成互补的两层：权限决定能用哪些工具、访问哪些文件和网址；沙箱在操作系统层面限制命令能碰哪些文件、能连哪些网络。文档特别指出，两层一起用的意义在于：**即使提示注入骗过了模型的判断，沙箱的限制仍然有效。**
- 本项目的做法比较朴素：文件工具限制在练习目录、命令执行前问人、命令最多跑 2 分钟（`run_command` 的超时）、作业的检查脚本留在程序这边不给学生和导师改。

## 常见误区
- ❌ "编程 Agent 用了什么特殊的新技术" → ✅ 就是工具（文件、搜索、终端）+ 循环 + 记忆 + 权限，前面每一课的零件组装起来
- ❌ "改文件就整个重写一遍" → ✅ 用精确修改只换需要改的那几行，并要求原文唯一，防止改错地方
- ❌ "把整个代码库都读进上下文最保险" → ✅ 先搜索定位、再按需读取，否则上下文很快被撑满
- ❌ "Agent 说做完了就是做完了" → ✅ 要用测试来验证，最好像真实用户一样端到端地测
- ❌ "在提示词里写'不许删文件'就安全了" → ✅ 要靠权限规则、hook 和沙箱这些程序层面的限制，模型可能被提示注入骗过
