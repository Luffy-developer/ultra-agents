# 第 5 课：Agent 循环

> **学完你能**：说清楚 Agent 和普通聊天机器人的区别；看懂一段 Agent 的运行记录；亲手写出一个不会死循环、出错也不会崩的 Agent 循环。

## 基础

### 1. Agent = 大模型 + 工具 + 循环 + 记忆
- 普通聊天机器人：你问一句，它答一句，结束。
- Agent：拿到任务后，**自己决定下一步做什么**——调用工具、看结果、再决定下一步……连续完成多步任务，直到它觉得可以交差了。
- 比喻：聊天机器人像问讯处，问一句答一句；Agent 像你请来的助理，交代一件事，它自己查资料、打电话、订位子，办完了再来汇报。

### 2. ReAct：想一想 → 做一步 → 看结果
Agent 循环最经典的模式叫 **ReAct**（Reasoning + Acting，边想边做）。每一轮有三步：
- **Thought（想）**：我现在知道什么，还缺什么，下一步该做什么
- **Action（做）**：调用一个工具，如 `get_weather(city="北京")`
- **Observation（看）**：拿到工具返回的结果，作为下一轮思考的依据

一段运行记录的例子（用户问"明天去北京要带伞吗"）：
```
Thought: 要知道北京明天的天气才能回答
Action: get_weather({"city": "北京", "days": 2})
Observation: 北京第 1 天：晴；北京第 2 天：小雨
Thought: 明天有小雨，信息够了，可以回答
最终回答: 明天北京有小雨，记得带伞
```
注意：Observation 是**工具返回的**，不是模型自己想出来的。模型说完 Action 就停下，等我们的代码执行工具、把结果交回去。

### 3. 循环的伪代码
```
messages = [system, user]
重复最多 N 次:
    回复 = 模型(messages, tools)
    if 回复没有调用工具:
        输出回复; 结束
    messages.append(回复)              # 模型想调用工具的这条回复也要放进对话
    for 每个工具调用:
        结果 = 执行工具
        messages.append(结果)          # 带上 tool_call_id
次数用完还没结束: 告诉用户"步骤太多，先停下了"
```

### 4. 什么时候停下来
循环一定要有出口，常见的有四种（来自 OpenAI 的 Agent 搭建指南）：
- 模型给出了不调用工具的回答（最常见）
- 模型调用了专门的「交差」工具（有的框架用这种方式让模型明确说"我做完了"）
- 出错了，而且自己改不好
- **达到最大轮数**：防止模型一直调用工具停不下来，白白烧钱

### 5. 先规划再动手
任务一长，模型容易做着做着忘了还剩哪几步。解决办法和人一样：**先列清单，做一项勾一项**。
- 本项目给导师准备了一个 `todo_write` 工具（`src/todo.ts`）：要做 3 步以上的任务时，导师先列出待办清单，开始做某一步就标成「进行中」，做完标成「已完成」。终端里的「⎿ [todo]待办清单」就是它，随时输入 `/todos` 也能查看
- 有意思的是，这个工具**什么实际的事都不做**，只是把清单记下来、显示出来。但模型每次更新清单时，都等于把"已经做完什么、接下来做什么"重新想了一遍——这就是**规划**
- Claude Code 的 Todo 列表也是一样的原理

## 进阶

### 1. 工具出错时：把错误交回给模型，但连续出错就停
（来自 12-factor-agents 第 9 条「把错误压缩进上下文」）
- 工具出错时不要让整个 Agent 崩掉，把错误信息作为工具结果交回给模型，模型往往能自己改正（比如把"背景"改成"北京"）
- 但如果**连续**出错好几次（常见做法是 3 次），说明模型自己改不好了，再试下去只会浪费钱，要停下来交给人处理
- 交回的错误信息要整理过：说清哪里错了、怎么改，不要把几十行调用栈原样塞回去
- 本项目：`src/agent.ts` 的 `runTool` 把工具抛出的错误包成 `{ error: … }` 交回给模型

### 2. 三种「下单」的写法
（来自 Hugging Face Agents Course 第 1 单元）
- **Function Calling**：用接口自带的 `tools` / `tool_calls`，本课和本项目用的都是它
- **JSON Agent**：让模型在回复里写一段 JSON，如 `{"action": "get_weather", "action_input": {"city": "北京"}}`，我们自己从文字里解析出来。没有 Function Calling 的模型也能用，但模型写完 Action 后要让它**停止生成**（stop and parse），否则它会自己编出一个假的 Observation
- **Code Agent**：让模型直接写一段代码来调用工具（如 `weather = get_weather("北京")`）。好处是能用循环、条件，一步做好几件事；坏处是要运行模型写的代码，**必须放在隔离的环境（沙箱）里**，否则有安全风险

### 3. 控制流掌握在自己手里
（来自 12-factor-agents 第 8 条）
- 循环是我们写的代码，所以可以在任何地方插一脚：模型选好工具后、真正执行前，先让人审批（本项目写文件、运行命令前弹出的「允许吗？」就是这个位置）
- 还可以在等人回复时把整个对话存起来、退出循环，等人回复了再接着跑——这在「生产级 Agent 工程」那一课里细讲

## 常见误区
- ❌ "Observation 是模型想出来的" → ✅ 是工具返回的结果，模型只负责 Thought 和 Action
- ❌ "模型想调用工具的那条回复不用放进对话" → ✅ 要原样放进去，否则模型看到一条 tool 结果却不知道是哪次调用的
- ❌ "模型很聪明，总会自己停下来" → ✅ 必须设最大轮数，否则可能无限循环、一直花钱
- ❌ "工具出错就重试，直到成功" → ✅ 要设连续出错的上限，超过就交给人
- ❌ "Agent 循环很复杂，得用框架" → ✅ 核心就是一个 for 循环，几十行代码就能写出来
