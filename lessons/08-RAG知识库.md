# 第 8 课：RAG 知识库

> **学完你能**：说清楚 RAG 解决什么问题、分哪几步；知道切块大小怎么取舍、为什么要让模型「照着资料答、没有就说不知道」；亲手写出一个能切块、检索、拼 Prompt 的迷你知识库。

## 基础

### 1. 模型的两个老毛病
- **不知道你的资料**：模型只学过训练时见过的公开内容。你公司的规章、你自己的笔记、昨天的新闻，它都没见过。
- **会一本正经地胡说八道**（幻觉）：不知道的时候，它不会老实说"不知道"，而是编一个听起来很像真的答案。
- RAG（Retrieval-Augmented Generation，检索增强生成）同时治这两个毛病：回答前，先从知识库里**查**出相关资料，塞进 Prompt，让模型**照着资料回答**。

### 2. 比喻：闭卷考试 vs 开卷考试
- 普通模型 = 闭卷考试，全凭记忆，记不清就瞎编
- RAG = 开卷考试，先翻书找到相关的那几段，再照着写答案
- 注意：开卷考试也得**会翻书**。翻错了页，照样答错——所以「检索」这一步是 RAG 的关键

### 3. 四个步骤
1. **切块**：把文档切成一小段一小段（比如每段几百字）
2. **向量化**：用 Embedding 模型把每段文字变成一串数字（向量）。意思相近的文字，向量也相近
3. **检索**：用户提问时，把问题也变成向量，找出最相近的几段
4. **生成**：把找到的段落 + 问题一起发给大模型，让它照着资料回答

其中 1、2 步可以提前做好、存起来（这就是"建知识库"）；3、4 步是每次提问时做的。

### 4. 切块：切多大？要不要重叠？
- **切太大**：一块里混着好几件事，检索时"沾点边"就被找出来，塞给模型一堆没用的内容，还占地方
- **切太小**：一句话被拆散，上半句在这块、下半句在那块，单独看哪块都说不清楚
- **重叠**：相邻两块之间留一小段重复的内容（比如每块 300 字，重叠 50 字），这样一句话正好被切在边界上时，至少有一块是完整的
- 没有万能的数字，要看文档长什么样：规章制度按"条"切、问答文档按"一问一答"切，往往比死板地按字数切效果好

### 5. 让模型「照着资料答，没有就说不知道」
光把资料塞进去还不够，Prompt 里要讲清规矩：
- **只根据下面的资料回答**，资料里没有的不要自己编
- **资料里找不到答案，就直接说"资料里没有"**——这比编一个错的答案有用得多
- **标出引用来源**：比如每段资料编上号 [1] [2]，回答时写"根据 [2]……"。这样人可以回去核对，模型也更不容易瞎编

再加一道保险：如果检索出来的段落**相关度都很低**（说明知识库里根本没有相关内容），干脆不调用模型，直接回答"资料里没有"。

### 6. 看看本项目
- 导师讲课前会调用 `read_lesson` 读讲义——这就是最简单的"检索"：按文件名查，整份讲义塞进上下文
- 讲义只有十几份、每份不长，这样做就够了。如果课程有几百份，整份塞进去会撑爆上下文，就要升级成按问题内容找相关段落的向量检索
- 第 9 课「让 Agent 上网」也是 RAG：资料来源从"自己的文档"换成了"整个互联网"

## 进阶

### 1. Agentic RAG：让 Agent 自己决定怎么查
（来自微软 AI Agents for Beginners 第 5 课）
- 普通 RAG 是固定流程：不管问什么，都先检索一次、再生成一次
- **Agentic RAG** 把检索做成一个**工具**交给 Agent（第 4 课「工具调用」），由它自己决定：
  - 要不要查（"你好"这种话不用查）
  - 查什么关键词、查哪个知识库
  - 查到的东西够不够，不够就**换个说法再查一次**
- 这其实就是第 5 课「Agent 循环」：想一想 → 查一次 → 看结果 → 再决定

### 2. Corrective RAG：先判断查到的东西靠不靠谱
- 向量检索只看"像不像"，不保证"有没有用"。比如问"年假几天"，可能查出一段讲"病假"的，因为字面很像
- 做法：检索出比较多的候选（比如 20 段），让模型（或专门的重排序模型）给每段打一个相关度分数，**只留下真正相关的几段**再交给模型回答
- 如果都不相关，就**改写问题再检索**（比如把"放假多久"改成"年假天数 规定"），或者老实回答"资料里没有"

### 3. 知识库投毒
（来自微软 AI Agents for Beginners 第 6 课）
- 知识库里的内容会被模型当成"可信资料"照着说。如果有人往里面塞了错误信息，或者藏一句"忽略之前的规则……"，模型就会被带偏——这叫**知识库投毒**
- 防护：
  - **限制写权限**：谁能往知识库里加内容，要管起来
  - **定期校验**：检查知识库里的内容有没有被篡改、有没有过时
  - **资料只是资料**：Prompt 里讲明，资料里出现的任何指令都不执行（和第 9 课「让 Agent 上网」防提示词注入是一个道理）

### 4. 工程上的几个取舍
- **检索几段（k）**：太少可能漏掉关键信息，太多又占上下文、引入噪声。常见做法是先多召回、再重排序筛掉
- **向量检索 + 关键词检索**：向量检索擅长"意思相近"，但对型号、人名、编号这类要精确匹配的词不灵，两种可以结合着用
- **上下文就是预算**：塞进去的资料越多，模型越容易抓不住重点（第 7 课「记忆与上下文工程」讲的"上下文腐烂"）

## 常见误区
- ❌ "用了 RAG，模型就不会胡说了" → ✅ 检索错了、资料本身错了，模型照样答错；还要在 Prompt 里要求"没有就说不知道"
- ❌ "块切得越小越精确" → ✅ 太小会把一句话拆散，单独看哪块都说不清；要按文档结构取舍，并加上重叠
- ❌ "检索出来的段落越多越好" → ✅ 不相关的段落会干扰模型，还占上下文
- ❌ "知识库是自己的，内容一定可信" → ✅ 也可能被人投毒或者过时，要管写权限、定期校验
- ❌ "RAG 就是固定的'先查再答'" → ✅ Agentic RAG 让 Agent 自己决定要不要查、查什么、查得够不够

## 动手作业（作业名：08-rag）
亲手写一个迷你知识库：把文档切成有重叠的块、按问题找出最相关的几块。
为了不花钱，这份作业用简单的「字符重叠」相似度代替 Embedding 向量，原理是一样的。
进阶档还要：拼出带编号资料、要求标注引用的 Prompt；相关度都太低时返回空，让程序直接回答"资料里没有"。
