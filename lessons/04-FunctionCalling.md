# 第 4 课：Function Calling（工具调用）

## 核心概念
- 模型自己不能做事，但它可以**说出"我想调用哪个工具、参数是什么"**，由我们的代码去真正执行。
- 流程：
  1. 我们把工具说明书（名字、用途、参数）通过 `tools` 参数发给模型
  2. 模型回复里出现 `tool_calls`：「请帮我调用 get_weather(city="北京")」
  3. 我们的代码执行这个函数，把结果以 `role: "tool"` 的消息发回给模型
  4. 模型看到结果后，组织成自然语言回答用户

## 比喻
模型是餐厅经理，工具是后厨。经理不亲自炒菜，只下单："来一份宫保鸡丁"。后厨做好端上来，经理再端给顾客。

## 进阶：Hooks——在工具调用前后插一脚
工具是模型决定要不要调用的，但有些事你希望**每次都必须发生**，不能靠模型自觉。这时用 **Hooks**（钩子）：
在特定的时刻，**程序**自动运行你写好的命令，不经过模型。
- 本项目支持 4 个时刻：工具调用前（`PreToolUse`）、工具调用后（`PostToolUse`）、你发消息后（`UserPromptSubmit`）、导师回答完（`Stop`）
- 例子：导师每写完一个文件就自动格式化；导师想运行带 `rm -rf` 的命令时直接拦下（命令以退出码 2 结束 = 拦下）
- 在 `~/.agent-tutor/hooks.json` 里设置，输入 `/hooks` 查看写法。Claude Code 的 Hooks 也是这个原理
- 和 System Prompt 里写"不许删文件"相比，hook 是**写死在程序里的规则**，模型怎么说都绕不过去

## 小测验
问：在 Function Calling 中，到底是谁真正执行了函数？
答：是我们自己的代码，模型只负责决定"调用哪个函数、传什么参数"。
